# 舞台灯光设备租赁管理系统

## 项目介绍

本系统是一个面向舞台灯光设备租赁业务的全栈管理系统，提供从设备台账管理、租赁合同管理、租赁订单处理、设备巡检记录到损坏赔扣确认的完整业务流程管理。系统采用 Node.js + Express 后端，SQLite 数据库，原生 HTML/JS 前端，实现了轻量级、易部署的业务管理解决方案。

## 功能模块

### 1. 设备台账管理
- 设备信息的增删改查
- 设备编码、名称、类型、型号、状态、日租金等属性管理
- 设备状态跟踪（可用、已出库、维修中、已报废等）

### 2. 租赁单管理
- 租赁订单创建与编辑
- 关联合同与设备明细
- 设备出库确认（记录出库操作员与时间）
- 客户归还确认（记录客户经办人与备注）
- 租赁单状态流转（待处理、已出库、已归还等）

### 3. 巡检记录管理
- 设备归还时的巡检记录录入
- 关联租赁单与具体设备
- 损坏情况标注与描述
- 巡检照片上传与管理
- 巡检员与巡检时间记录

### 4. 赔扣确认管理
- 基于巡检记录创建赔扣单
- 赔扣金额与原因录入
- 赔扣单状态跟踪（待处理、已确认、已结算等）
- 会计人员确认记录

### 5. 合同状态流转
- 合同信息管理（合同号、客户、项目、起止日期、金额等）
- 合同状态管理（草稿、执行中、已完成、已归档等）
- 合同归档操作（需满足业务规则约束）
- 关联租赁订单查询

## 三大业务规则验证点说明

### 规则一：未出库设备禁止生成巡检任务
- **验证点**：创建巡检记录时，系统自动校验关联设备是否已完成出库
- **实现位置**：`backend/src/middleware/validation.js:4-13`
- **业务逻辑**：只有已完成出库确认的设备才能生成巡检任务，防止对未出库设备进行虚假巡检

### 规则二：无损坏照片不得录入赔扣金额
- **验证点**：创建赔扣单时，系统校验关联的巡检记录
- **实现位置**：`backend/src/middleware/validation.js:15-23`
- **业务逻辑**：
  1. 赔扣单必须关联巡检记录
  2. 关联的巡检记录必须标注有损坏（has_damage = 1）
  3. 巡检记录必须上传至少一张损坏照片
- **目的**：确保赔扣有凭有据，防止无依据扣费

### 规则三：客户未确认归还禁止归档合同
- **验证点**：合同归档操作时，校验关联的所有租赁单
- **实现位置**：`backend/src/middleware/validation.js:25-35`
- **业务逻辑**：合同下的所有租赁订单必须完成客户归还确认后，才能进行归档操作
- **目的**：确保合同完结前所有设备已归还，避免归档后出现设备遗失纠纷

## 启动步骤

### 1. 安装依赖

```bash
cd backend
npm install
```

### 2. 初始化数据库

数据库会在首次启动时自动初始化，也可以手动执行：

```bash
cd backend
node -e "require('./src/models/database')"
```

### 3. 导入种子数据

```bash
cd backend
npm run seed
```

### 4. 启动服务

开发模式（自动重启）：
```bash
cd backend
npm run dev
```

生产模式：
```bash
cd backend
npm start
```

服务启动后将监听 `http://localhost:3001`

## 前端访问方式

启动后端服务后，在浏览器中访问：

```
http://localhost:3001
```

系统将自动加载前端页面，包含完整的功能导航与操作界面。

## 端到端测试命令

```bash
cd backend
node scripts/e2e-test.js
```

测试脚本将验证：
- 服务健康检查接口
- 各模块 API 接口可用性
- 业务规则校验逻辑
- 数据增删改查功能
